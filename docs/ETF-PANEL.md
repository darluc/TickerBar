# ETF 面板：实现方式与静态内容

记录日期：2026-11-07。以提交 `9359e5a`（`2026.4.14` 对应代码）及仓库内种子文件为准。本文记录已实现行为；历史文件格式和导入操作见 [ETF-HISTORY.md](ETF-HISTORY.md)。

## 1. 实现方式

### 原生界面与入口

面板使用 **SwiftUI + Swift Charts + AppKit 窗口容器**，没有嵌入原站网页，也不加载 ECharts、远程 JavaScript 或原站 Service Worker。

- 菜单栏弹窗和置顶浮窗均使用 `PopoverRoot`；顶部通过「自选 / ETF 资金」分段按钮选择内容。
- `DependencyContainer` 持有一个共享的 `ETFMonitor`，分别注入两种窗口。因此钉住、取消钉住时保留 ETF 选择和已加载数据。
- 顶部页面选择使用 UserDefaults 键 `etfPanelSelected` 持久化；内部子页、暂停状态、历史日期选择不持久化，进程初始子页为「盘中量能」。
- ETF 页复用顶部刷新、钉住、设置按钮和底部状态栏；隐藏自选搜索入口。刷新按钮根据当前页面调用 ETF 或普通行情刷新器。
- 内容采用 `ScrollView + LazyVStack`。分钟图拖选状态位于独立的 `ETFMinuteChart`，不通过整个页面的状态驱动重绘。

### 职责与代码入口

下表路径均相对仓库根目录。

| 文件或类型 | 职责 |
| --- | --- |
| `TickerBar/ETF/ETFPanel.swift` | 三个子页、卡片、图表、排名、拖选、导入导出入口 |
| `TickerBar/ETF/ETFMonitor.swift` | MainActor 上的页面状态、调度、暂停、错误状态和展示快照发布 |
| `TickerBar/ETF/ETFPresentation.swift`：`ETFPresentation` | 根据一批采集数据和历史生成展示缓存，包括合计、覆盖率、曲线、均值和分类累计 |
| 同上：`ETFDataWorker` | 独立 actor，执行历史解码、分钟归并、展示数据计算、导入导出和磁盘读写 |
| `TickerBar/ETF/ETFService.swift`：`ETFService` | 东方财富 HTTP 请求及响应解析 |
| 同上：`ETFStore` | `capture.json`、`history.json` 的读取、原子写入和分钟去重 |
| `TickerBar/ETF/ETFData.swift` | 固定标的清单、时间轴、基础模型、分钟聚合、历史格式校验 |
| `TickerBar/Resources/etf-history-seed.json` | 随 App 打包的历史种子，离线可读 |
| `scripts/import-etf-seed.py` | 将已授权取得的原站历史文件离线转换为本地格式 |

### 数据与线程流转

```text
首次进入 ETF 页
  → ETFMonitor.run / loadIfNeeded（多个调用共享一次加载任务）
  → ETFDataWorker.load（后台读取 capture、history 或包内种子）
  → ETFPresentation.build（后台准备展示缓存）
  → MainActor 一次发布 display → SwiftUI / Swift Charts

一轮采集
  → 批量行情快照 → 后台准备缓存 → 发布
  → 21 路分时请求分组执行 → 后台归并、保存、准备缓存 → 发布
  → 如需补日线：逐只获取 → 后台保存、准备缓存 → 发布
```

`capture` 与 `history` 原始档案不逐项触发 UI 发布。页面读取的合计、曲线、均值、日期索引来自 `display` 缓存；滚动和拖选不重新扫描历史。后台按交易日一次分组分钟记录，再聚合各日曲线。不得将全量聚合或大文件编解码重新放回 View 的计算属性或 MainActor。

### 请求与刷新规则

原站只用于初始历史资料，**App 运行时直接请求东方财富并保存本地，不依赖原站登录、接口或密码**。请求经项目 `HTTPClient / NetworkConfig`，沿用代理设置；ETF 数据源没有接入普通行情的多供应商 fallback。

| 用途 | 地址及关键参数 | 实际采用的数据 |
| --- | --- | --- |
| 快照 | `https://push2.eastmoney.com/api/qt/ulist.np/get`；`fltt=2`、`invt=2`；`secids` 包含固定 20 只及 `1.000001` | `f12` 代码、`f6` 成交额、`f3` 百分数、`f124` Unix 秒时间戳；`f13/f2/f18` 虽请求但不存入 ETF 快照模型 |
| 分钟 | `https://push2.eastmoney.com/api/qt/stock/trends2/get`；逐证券 `secid`，`ndays=5`、`iscr=0`，请求 `f51` 至 `f58` | 返回 CSV 第 0 列时间、第 2 列价格、第 6 列成交额；每条为独立分钟数据 |
| 日线 | `https://push2his.eastmoney.com/api/qt/stock/kline/get`；`klt=101`、`fqt=0`、`lmt=65`、`end=20500101` | 日期和第 6 列日成交额，仅用于回补成交额 |

- 打开 ETF 页先读取本地档案，未暂停则立即采集一轮；这次即时采集不受开盘时段限制。
- 后续循环每轮等待 60 秒，再按 `MarketClock.status(.a)` 决定是否采集；间隔不包含上一轮请求耗时。午休和休市不自动发起新一轮。
- 时区固定 `Asia/Shanghai`；常规开盘区间为 09:30—11:30、13:00—15:00，排除周末，支持项目已有的当天开闭市覆盖设置；没有完整节假日日历。
- 分时最多 4 路并发，21 个目标分批请求；没有沿用原站的 `/api/ktrends` 批量代理。日线目前逐只顺序请求，单请求超时 12 秒。
- 日线成功完成后记录 `dailyUpdated`，同一北京时间自然日不重复补齐；失败在下一轮重试。展示历史篮子成交额时，只采用早于今天且 20 只日线齐全的日期。
- 暂停阻止新的自动请求，已发出的请求可完成；手动刷新仍可用。内部三个子页共享这一套调度。
- ETF 页的 `.task` 持有自动循环；任务取消后退出。窗口隐藏、钉住等实际生命周期效果需结合 AppKit 容器验证，不能仅凭 `.task` 就认定所有隐藏场景均已验收。

## 2. 固定内容与展示规则

### 顶部、菜单与状态

| 位置 | 当前内容 |
| --- | --- |
| 标题 | 宽基 ETF 资金监控 |
| 副标题 | 固定 20 只 · 2026-10-15 篮子 · 金额单位：亿元 |
| 外层入口 | `tab.etf`：ETF 资金 / ETF Capital |
| 子页一 | `etf.section.intraday`：盘中量能 / Intraday |
| 子页二 | `etf.section.flows`：申赎与放量 / Flows |
| 子页三 | `etf.section.broad`：全市场宽基 / Broad Market |
| 暂停按钮 | `pause.fill / play.fill`；提示「暂停所有 ETF 自动采集 / 恢复自动采集」 |
| 存储菜单 | 导入本地历史 JSON；导出完整本地档案 |

入口和三个子页标签已经进入 `Localizable.xcstrings`，大多数正文、说明和错误文案仍为代码中的中文字符串；尚未完整双语化。

底部状态按优先级显示：暂停 → 采集中 → 错误 → 等待首次采集 → 非今日交易数据 → 超过 180 秒的本地缓存 → 当前交易时段状态。日期来自数据，不把缓存当作当前实时数据。暂停、午休、休市状态均有独立文字；错误长文本可通过悬停查看。

### 三个子页

| 子页 | 内容顺序与交互 |
| --- | --- |
| 盘中量能 | 篮子成交额与最新历史申赎卡片 → 不完整提示 → 分钟成交额柱图 → 上证综指独立点位轴折线 → 当前、历史对比日、20 日均值累计图 → 日期与插值说明 → 成交额排名 |
| 申赎与放量 | 最近历史申赎卡片及截止说明 → 最近 60 个有申赎记录交易日柱图 → 日期选择 → 当日成交额、当日申赎卡片及放量判断 → 原站预计算样本说明 → 数据来源 |
| 全市场宽基 | 独立统计范围说明 → 最新分类合计卡片 → 最近 30 个分类记录日堆积柱图 → 全部分类历史累计折线 → 最新日期分类金额列表 → 数据来源 |

- 盘中分钟柱图高度 125 pt，上证综指 75 pt，累计对比图 155 pt；申赎柱图 150 pt，全市场柱图 155 pt、累计线 100 pt。
- 分钟坐标压缩午休：`09:30→0`、`11:30→120`、`13:00→121`、`15:00→241`；显示刻度为 09:30、10:30、11:30、14:00、15:00。
- 分钟图拖选只汇总所选分钟柱的成交额，并显示选区最低覆盖数；不累加指数或累计曲线。相同选区不重复写入状态。
- 当前累计线为蓝色，历史对比为橙色，20 日均值为灰色虚线；覆盖完整的分钟柱为蓝色，不完整为橙色。涨跌幅、申赎及分类金额方向色沿用用户的涨跌配色设置。
- 排名按有效快照成交额降序，相同金额按代码排序。列为「ETF、成交额、占比、涨跌幅」，名称下显示代码和快照时间；背景条长度相对当前最大成交额。
- 金额显示两位小数；排名占比一位小数，涨跌幅带正负号和两位小数；缺失金额或涨跌幅显示 `—`。

## 4. 数据口径、存储与限制

### 合计与历史对比

- 快照成交额为有效 ETF 快照之和；占比为单只成交额 ÷ 此合计。不足 20 只时明确显示「已覆盖标的成交额」「非完整篮子占比」。
- 分钟成交额为同一交易日、同一分钟各 ETF 成交额之和，累计值按分钟递增累加；保留每分钟实际覆盖数。缺失会导致部分合计低估，不伪造真实的零值，也没有原站的 16/20 才绘图门槛。
- 展示交易日优先取 ETF 快照中的最新北京时间日期；没有 ETF 快照时才从存储分钟记录中取最新日。快照与分钟独立采集，不强制两者总额相等。
- 可用的本地完整历史日须从 09:30 到 15:00、去除可选 13:00 后含 241 个槽位，且各槽位均覆盖 20 只。这些曲线优先替换同日种子曲线。
- 积累 20 个本地完整历史日且时间轴一致后，取最新 20 日逐分钟算术均值；此前使用种子均值并展示其真实日期区间及插值标记。
- 申赎与成交额独立存储，放量判断严格为 `basketNetFlow > 100 × 1e8`，等于 100 亿不触发。没有实时申赎、主力大单或机构身份识别。
- 全市场累计线由当前档案中分类金额从最早日期逐日累加；没有把 20 只篮子的合计替代全市场。

### 本地保存

固定目录为 `~/Library/Application Support/TickerBar/ETF/`。**ETF 目录目前不随 Debug/Release 的 CFBundleName 分开**，与普通自选数据库的隔离规则不同。

| 文件 | 结构和行为 |
| --- | --- |
| `history.json` | 版本化历史、分类、对比曲线与样本摘要；优先读取本地合法文件，否则读取包内种子；仅当本地文件不存在时写入种子 |
| `capture.json` | `quotes`、按代码组织的 `minutes`、按代码/日期组织的 `daily`、`updated`、`dailyUpdated`；最新批次覆盖快照，分钟按时间去重且新值优先，日线按日期合并 |
| 完整档案导出 | `{capture, history}`，文件名 `etf-archive-YYYY-MM-DD.json`；与纯历史导入格式不同 |

当前采用原子 JSON 写入，不使用 ETF 专属 SQLite 表。分钟和日线记录没有自动过期清理；`Date` 沿用 JSONEncoder/Decoder 默认时间策略，不能将 `capture` 中日期数字直接当作上游 Unix 秒。历史 JSON 的详细字段、校验和恢复操作见 [ETF-HISTORY.md](ETF-HISTORY.md)。

### 已知边界与维护要求

- 自动采集仅更新快照、分钟和日成交额。**申赎、全市场分类及样本摘要仍靠种子或导入更新**，不能称为每天自动更新的 T-1 链路。
- 原站历史的生成细节、样本排除原因和申赎公式未核实；不能根据通用经验补写为已验证算法。
- `2026.4.14` 将重计算移出主线程并减少 UI 发布，已有 GitHub 构建/回归证据；实际机器上的 CPU 降幅和完整交互流畅度尚未作为验收结果记录。
- 曾发生多个自选列表包含同一证券，普通行情解析用唯一键字典直接崩溃；修复位于行情编排与供应商解析层。ETF 页并不停止普通行情刷新，维护时必须保留跨组请求去重和解析容错，不能删除用户的合法跨组自选来规避。
- 改篮子、分类、样本或截止日期时，同步更新本文与历史文件说明；改代码时新增文件以 `project.yml` 的源目录自动纳入 Xcode 工程。

已有定向测试位于 `TickerBarTests/ETFMonitorTests.swift` 和 `TickerBarTests/DuplicateQuoteSymbolsTests.swift`，覆盖单位、日期边界、聚合覆盖率、历史种子、展示缓存口径及重复证券。文档修改不需要本地 App 构建。
